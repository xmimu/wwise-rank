## 1. 简介

Wwise Rank 是一款运行在 Windows 桌面的悬浮窗小工具，专为 Wwise 音频工程师设计。它通过 **WAAPI（Wwise Authoring API）** 监听你在 Wwise 中的实际操作，并以积分形式量化工作投入，让你能够直观感知当前的操作节奏与累计工作量。

**适用场景：**

- 个人工作效率追踪
- 团队工作量可视化
- 学习过程中的操作频次统计

## 2. 安装与启动

### 2.1 直接使用（推荐）

从发布页面下载安装包（`.msi`），双击安装后启动 `wwise-rank.exe` 即可。

应用以透明悬浮窗形式出现在屏幕上，默认置顶显示。

### 2.2 从源码构建

**环境要求：**

| 工具 | 最低版本 |
|------|----------|
| Rust | 1.70+ |
| Node.js | 18+ |
| pnpm | 8+ |

**步骤：**

```bash
# 克隆仓库
git clone <仓库地址>
cd wwise-rank

# 安装前端依赖
pnpm install

# 开发模式（热重载）
pnpm tauri dev

# 构建发布包
pnpm tauri build
```

### 2.3 启动前准备

启动 Wwise Rank 前，请确保：

1. Wwise 已打开并加载了工程
2. Wwise 的 **WAAPI（本地 WebSocket 服务）** 已启用

启用 WAAPI 的方法：Wwise 菜单 → **Project** → **User Preferences** → 勾选 **Enable WAAPI**，端口保持默认（`8080`）。

## 3. 界面说明

应用窗口为 320×200 像素的无边框透明悬浮窗，分为以下区域：

```
┌─────────────────────────────────────┐
│  ≡  Wwise Rank          📌          │  ← 标题栏（拖拽区）
├─────────────────────────────────────┤
│  状态指示灯   [████████░░░░] VU 表头 │  ← 连接状态 & 活跃度
├──────────────────┬──────────────────┤
│   Rank           │   Session        │  ← 双模式计分
│   12,480         │   360            │
└──────────────────┴──────────────────┘
```

### 3.1 标题栏

| 元素 | 功能 |
|------|------|
| `≡` 汉堡图标 | 点击（预留，暂无功能） |
| 标题区域 | 按住拖拽可移动窗口 |
| `📌` 图钉图标 | 切换窗口置顶 / 取消置顶 |

**窗口吸附：** 拖拽窗口靠近屏幕边缘 24px 以内时，会自动吸附到边缘。

### 3.2 连接状态指示

| 状态 | 颜色 | 说明 |
|------|------|------|
| Idle | 灰色 | 未扫描，空闲 |
| Scanning | 黄色（闪烁） | 正在扫描可用端口 |
| Connected | 绿色 | 已连接到 Wwise，正常监听 |

### 3.3 VU 表头（活跃度指示器）

24 段横向色条，反映**最近一段时间内的事件触发频率**。操作越密集，亮起的段数越多；停止操作后，亮度会逐渐衰减至零。

### 3.4 计分区域

| 模块 | 说明 |
|------|------|
| **Rank**（总排名分） | 自安装起累计的总分，跨会话持久化保存，不会因重启清零 |
| **Session**（本次会话分） | 本次启动后获得的分数，重启应用后归零 |

分数变化时会有发光动画提示。

## 4. 连接 Wwise

### 4.1 自动连接流程

应用启动后会自动进行以下步骤，无需手动操作：

1. **TCP 端口探测** — 依次扫描 `8080`、`8081`、`8082`、`8083`，找到监听端口
2. **WebSocket 握手** — 与 Wwise WAAPI 建立 WebSocket 连接
3. **就绪检测** — 调用 `getInfo` 接口确认 Wwise 已完全就绪
4. **事件订阅** — 订阅全部 22 种 WAAPI Topic，开始接收操作事件

### 4.2 断线重连

连接中断后，应用会按照指数退避策略自动重连：

- 初始等待约 **1.5 秒**
- 每次失败后等待时间加倍
- 最长等待不超过 **30 秒**

只要 Wwise 重新可用，应用会自动恢复连接，**无需手动干预**。

## 5. 积分系统

### 5.1 积分原则

分值依据操作的**复杂度与影响范围**设计：

- 创建、生成、结构性变更等高复杂度操作得分高（4–5 分）
- 属性调整、曲线编辑等中等操作居中（3–4 分）
- 重命名、备注、选择等低复杂度操作得分低（1–2 分）

### 5.2 完整计分表

详见 [操作计分表](操作计分表.md)，以下为简要汇总：

| 分值 | 操作类型 |
|------|----------|
| **5 分** | 创建对象、结构更改、SoundBank 生成（单个/完成） |
| **4 分** | 导入音频、引用更改、Switch Container 指派添加 |
| **3 分** | 添加子对象、删除对象、曲线更改、属性更改、工程加载/保存、走带状态变化、Switch Container 指派移除 |
| **2 分** | 移除子对象、重命名对象、工程关闭 |
| **1 分** | Attenuation 曲线更改、Attenuation 曲线 Link 切换、修改备注、选择变更 |

## 6. 自定义积分配置

### 6.1 配置文件位置

应用首次运行后，会在系统应用数据目录自动生成 `score_config.json`。

**Windows 路径：**

```
%APPDATA%\com.tauri-app.wwise-rank\score_config.json
```

（通常为 `C:\Users\<用户名>\AppData\Roaming\com.tauri-app.wwise-rank\`）

### 6.2 配置文件格式

文件为 JSON 格式，键为 WAAPI Topic 名称，值为对应分数（整数）：

```json
{
  "ak.wwise.core.object.created": 5,
  "ak.wwise.core.object.nameChanged": 2,
  "ak.wwise.core.audio.imported": 4,
  "ak.wwise.ui.selectionChanged": 1
}
```

**所有可用 Topic 键名：**

| Topic | 默认分值 |
|-------|----------|
| `ak.wwise.core.audio.imported` | 4 |
| `ak.wwise.core.object.attenuationCurveChanged` | 1 |
| `ak.wwise.core.object.attenuationCurveLinkChanged` | 1 |
| `ak.wwise.core.object.childAdded` | 3 |
| `ak.wwise.core.object.childRemoved` | 2 |
| `ak.wwise.core.object.created` | 5 |
| `ak.wwise.core.object.curveChanged` | 3 |
| `ak.wwise.core.object.nameChanged` | 2 |
| `ak.wwise.core.object.notesChanged` | 1 |
| `ak.wwise.core.object.postDeleted` | 3 |
| `ak.wwise.core.object.propertyChanged` | 3 |
| `ak.wwise.core.object.referenceChanged` | 4 |
| `ak.wwise.core.object.structureChanged` | 5 |
| `ak.wwise.core.project.loaded` | 3 |
| `ak.wwise.core.project.postClosed` | 2 |
| `ak.wwise.core.project.saved` | 3 |
| `ak.wwise.core.soundbank.generated` | 5 |
| `ak.wwise.core.soundbank.generationDone` | 5 |
| `ak.wwise.core.switchContainer.assignmentAdded` | 4 |
| `ak.wwise.core.switchContainer.assignmentRemoved` | 3 |
| `ak.wwise.core.transport.stateChanged` | 3 |
| `ak.wwise.ui.selectionChanged` | 1 |

### 6.3 修改方式

1. 关闭 Wwise Rank（可选，热加载未实现，修改后需重启生效）
2. 用文本编辑器打开 `score_config.json`
3. 修改对应 Topic 的数值（只需填写想要修改的项，其余保持默认）
4. 保存文件后重启应用

**注意：** 配置文件中不存在的 Topic 键名会使用内置默认值，不会报错。

## 7. 数据持久化

### 7.1 数据文件

| 文件 | 内容 | 位置 |
|------|------|------|
| `score.json` | 总分（`total_score`）+ 各 Topic 累计触发次数 | 应用数据目录 |
| `score_config.json` | 自定义分值配置 | 应用数据目录 |

### 7.2 写入策略

为避免频繁磁盘写入，应用采用**脏标记 + 定时批量写入**策略：

- 每次收到事件后，仅在内存中更新分数并标记为「脏」
- 每隔约 **3 秒** 检查一次脏标记，有变化才写入磁盘

因此，若应用意外关闭，最多可能丢失最近 3 秒内的分数变化。

### 7.3 重置积分

如需重置 Rank 总分：

1. 关闭 Wwise Rank
2. 找到 `score.json`，将 `total_score` 字段改为 `0`（或直接删除整个文件）
3. 重启应用

## 8. 高级配置（环境变量）

所有网络超时参数均可通过环境变量覆盖默认值，适合网络环境特殊或 Wwise 启动较慢的情况：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `WWAAPI_TCP_PROBE_MS` | `300` | TCP 端口探测超时（毫秒） |
| `WWAAPI_CONNECT_SECS` | `4` | WebSocket 连接超时（秒） |
| `WWAAPI_GETINFO_SECS` | `3` | WAAPI 就绪检测超时（秒） |
| `WWAAPI_SUBSCRIBE_SECS` | `5` | 单个 Topic 订阅超时（秒） |
| `WWAAPI_DISCONNECT_SECS` | `2` | 断线检测超时（秒） |
| `WWAAPI_BACKOFF_INITIAL_MS` | `1500` | 重连初始等待（毫秒） |
| `WWAAPI_BACKOFF_MAX_MS` | `30000` | 重连最大等待（毫秒） |

**设置方式（PowerShell）：**

```powershell
$env:WWAAPI_CONNECT_SECS = "8"
.\wwise-rank.exe
```

或通过系统「环境变量」设置持久生效。

## 9. 常见问题

### Q: 应用启动后一直显示 Scanning，无法连接

**可能原因与解决方法：**

1. Wwise 未打开 → 打开 Wwise 并加载工程
2. WAAPI 未启用 → 在 Wwise 中开启 WAAPI（参见第 2.3 节）
3. Wwise 使用了非默认端口（不在 8080–8083 范围内）→ 在 Wwise User Preferences 中将端口改为 8080–8083 之一
4. 防火墙阻止了本地 WebSocket 连接 → 检查 Windows Defender 或其他防火墙设置，允许本地回环连接

---

### Q: 分数没有变化，但 Wwise 中有操作

**可能原因：**

1. 未处于 Connected 状态 → 确认状态指示为绿色 Connected
2. 触发的事件类型不在监听列表中 → 参考 [操作计分表](操作计分表.md) 确认操作是否在支持范围内

---

### Q: 如何完全重置所有数据

删除应用数据目录下的 `score.json` 和 `score_config.json`，重启应用后将重新生成默认配置，总分归零。

---

### Q: 应用窗口消失了，找不到

- 可能被移到了屏幕之外。在任务栏右键点击应用图标，选择「移动」，然后用方向键将窗口移回屏幕可见区域。
- 如果任务栏也找不到，可直接重启应用，窗口会回到默认位置。

---

### Q: 积分配置文件改了，分数没变

`score_config.json` 在应用启动时加载，修改后需**重启 Wwise Rank** 才能生效。
